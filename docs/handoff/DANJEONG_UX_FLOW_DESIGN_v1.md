## 3. To-Be — 한 화면·한 결정, 3축 시방

### 3.1 To-Be 흐름 (요약)

```text
Step0 /make · 용도 선택        [이력서 | 링크드인 | 인화용] → 다음
Step1 /make · 셀카 받기         [촬영 | 앨범에서 선택] → 미리보기 → (다시 올리기) → 다음   ← 3.2
Step2 /make · 분위기(기본값 우선) [모습·나이·추가프롬프트] · "기본값으로 계속" 동급 버튼    ← 3.3
Step3 /make · 팩 선택+선택요약   [팩] → 선택요약카드(용도/모습/나이/팩/금액) → 약관(접힘) → 결제 ← 3.4
        ↓ (기존 유지 — CONCURRENCY.md 대응)
        /make/payment/success
        ↓
Step4 /result · 생성 대기        FirstCutButton (기존 유지)
Step5 /result · 컷 고르기        PreviewStep — 업셀 문구 제거, 선택 즉시 "다음: 저장 ↓" 고정 CTA로 연결
Step6 /result · 받기            저장 전용 화면 — 업셀 요소 없음, 저장 성공 즉시 완료 배지     ← 3.4
        ↓ (저장 완료 후에만 진입 가능)
Step7 /result · 더 받기          인화규격 · 나머지 전부 · 추가컷 · 이메일전달(별도 섹션/아코디언)
        ↓ (전 스텝 공통, 상시 노출)
        CS 입구 고정 링크 · 다시 만들기(redo/asv) 진입점 고정 노출
```

기존 상태머신 `resolveMakeFlowStep`(`setup/checkout/paidFirst/paidDone`, `src/lib/flow/makeFlow.ts:19-24`)은 유지하고, `setup`과 `paidDone` 내부를 위 서브스텝으로 세분화하는 확장으로 구현 가능 — 상태머신 전면 교체 불필요.

### 3.2 파일 받기 시방

| 항목 | 시방 |
|---|---|
| 포맷 | JPG/PNG/HEIC 허용 라벨을 드롭존에 명시(`accept` 값은 유지) |

| 정보 구조 | 용도(Step0) → 분위기·나이·추가프롬프트(Step2) → 팩(Step3) 3단 분리, 진행 인디케이터 공통 컴포넌트로 노출 |
| 기본값 | 각 옵션 그룹에 "사진 그대로/기본값으로 계속" 버튼을 다른 선택지와 동일한 크기·강조로 배치 |
| 가격 연동 | Step2(모습/나이/추가)에는 가격 미노출, Step3(팩)에만 가격+합계 노출 — "이 옵션이 값을 바꾸는지"에 대한 오인 차단 |
| 되돌리기 | 스텝 상단에 "이전" 이동 가능, 이동해도 이미 입력한 셀카·옵션 값은 유지(현재도 state가 `MakeStudio` 레벨이라 보존됨 — 문구로 명시만 추가) |

## 4. 촬영자 다음 주 — 사람 손 구간 vs 자동 구간 경계

```text
[사람 손]                              [자동 — 이 문서의 범위]
대상자 상담·확인                              │
        ↓                                    │
촬영자 현장 방문·촬영                          │
(GPS 체크인 · PWA · role badge           │  ← 이 도구는 미설계.
 — 이 문서 비범위, 별도 발주)                  │    HARD 제약: worker/GPS/PWA/role badge ✗
        ↓                                    │
촬영자가 촬영본을 /make에 업로드  ─────────→  [Step1 셀카 받기]부터 동일 자동 파이프라인
                                              (생성 → 컷 고르기 → 받기)
        ↑                                    │
인화·액자 결합·전달 (협력업체)  ←──────────  [Step6/7 받기·더 받기]에서 나온 인화용 파일
```

- 이 설계가 보장하는 것은 단 하나: **"누가 셀카를 올리든(본인 또는 촬영자 대리) `/make`의 자동 구간 입구는 동일하다"**는 인터페이스뿐.
- 촬영자용 worker 앱·GPS 체크인·PWA·role badge는 이번 문서에서 설계하지 않음(HARD 비범위) — 필요 시 별도 발주.
- 배경 맥락(참고, 인용만): [`PIPELINE.md`](../PIPELINE.md) YJ-01(여주시 영정복지), [`FLOW_영정복지_제작전달.md`](../FLOW_영정복지_제작전달.md).

## 5. 우선순위

1. 결제 전 "선택 확인" 요약 카드 추가(`CheckoutStep.tsx`) — 용도/모습/나이/팩/금액 한눈에, 법적 문단은 접이식으로 축약
