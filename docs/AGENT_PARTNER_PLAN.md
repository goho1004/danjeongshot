---

## 1. 한 줄

**폰 하나 + 전용 링크로 ‘단정 증명사진 안내소’를 까는 개인·소호 대리망.**  
공식 표기는 **가맹·사진관 개업 ✗** · **모바일 안내 파트너(제휴) ○**.

마케팅 훅(숏폼·당근·SNS): 「본인 핸드폰만으로 사진관 개업」**허용**.  
계약·약관·세금·공식 상호: **제휴·안내 파트너**만.

---

## 2. 왜 하는가

| 니즈 | 단정 답 |
|------|---------|
| 구직자 이력서 사진이 급함 | 셀카 → 약 1분 → PNG |
| 현장·학원·인력사무소에 사진관 없음 | 사람+QR이면 충분 |
| 대리 입장 CapEx | 폰·데이터만 · 임대·조명·배경 ✗ |
| 본사 | 대형 B2B와 **별 레인**으로 저변 확대 |

원가 감각(연구): 컷≈₩50 · PG≈3.7% · 버퍼 소량 → **원가율 ~8%**.  
채널 마진을 줘도 남는 구조. 위험은 **비율 스택·남용**.

## 3. 포지션 · 하지 말 것

### 한다
- 개인/소호 **제휴 파트너** (소개·현장 안내)
- 전용 `?partner=` / 넘버링 QR · 월 인센 정산
- **당근·SNS 노출 영업**으로 파트너·이용자 모집 (전봇대·무차별 QR 살포는 여전히 ✗)

### 안 한다
| 금지 | 이유 |
|------|------|
| **가맹점·가맹비·영업지역** | 가맹사업법·의무고지 리스크 |
| 「여권·관공서 OK」 | 제품 정책 위반 |
| 대리 = 법인 B2B 40~50%와 **동일 코드** | 귀속·단가 충돌 |
| 인센 **풀스택** (법인% + 개인% 동시) | 마진 붕괴 |
| 애드센스식 **70%를 개인 대리 기본** | 잔여 얇음 · 가격 주도권 상실 |
| 무작위 QR 살포 | [`MARKETING.md`](MARKETING.md) 금지와 동일 |

## 4. 채널 레인 (충돌 방지)

```text
[A] 법인 B2B (인력아웃소싱 대형)
    임원 탑다운 · 채널 마진 40~50%(협의) · 업체 코드

[B] 모바일 대리 (본 기획)
    개인/소호 · 인센 15~25% · 개인 코드

[C] 소비자 직접 / 쇼츠·학내 할인
    기존 캠페인 · 대리·B2B와 스택 ✗
```

**규칙:** 한 결제에 코드 **1개만**. A∩B 중복 귀속 ✗.  
같은 인력사 건물 안이어도 **법인 계약이 있으면 A 우선**, 개인 대리 신규 중단 또는 법인 내부 인센으로만.

## 6. 인센·정산 (초안 · 미확정)

| 유형 | 율(결제액) | 비고 |
|------|------------|------|
| 모바일 대리 | **15~25%** | **기준 20% 잠금** · 협의 ±5% |
| 사장·임원 소개(기존) | 10~20% | 대리와 **동일 층** · 코드만 구분 |
| 법인 B2B | 40~50% | **레인 A만** |
| 독점·초대형 | ~70% 협의 | 예외 · 개인 대리 ✗ |

**정산 (요약)** — 상세는 §16 · 채널 정본 [`MARKETING_CHANNEL.md`](MARKETING_CHANNEL.md)  
- **모델:** B2B·개인 모두 **대리점** · 코드별 율 · QR/코드 인증  
- **주기 (마케팅 잠금):** 법인=**월 또는 주** · 개인=**주** (목표 **일/준즉시**)  
- 기준: 대리점코드로 **결제 확정** 건 (환불·차지백 차감) · 율은 코드 스냅샷  
- 지급: 법인→**세금계산서** / 개인→**원천** (사업자 등록 후)  
- **가맹비 ✗ · 환불보증금 ○** — 당기 유보 **≤GMV 5%** · 장기 잔고 목표 **20% 램프** · B2B 환불=다음주기 감 · 목표 도달 후 개인 유보 현금영향≈중립 ([`MARKETING_CHANNEL.md`](MARKETING_CHANNEL.md) §4-3-a)  
- 최소 지급액: 예) ₩30,000 미만 이월 (개인 일·주 배치와 맞춤)  
- **온라인 ○ · 완전 자동은 단계적** (아래 §16)

**원가 잔여 감각 (기본 ₩9,900 · 현실 2컷 · 버퍼 3%)**
- 대리 20% → 단정 잔여 ≈ **₩6.7천대** (여유)
- 대리 25% → ≈ **₩6.2천대**
- 법인 50% 또는 70%는 본 기획 기본안 **밖**

## 7. 파트너 여정

1. **모집** — 핀포인트 초대 (카톡·대면). 공개 대규모 모집 ✗ (베타 중)
2. **온보딩** — 1페이지 가이드 + 금지항 + 전용 링크/QR 발급 · 대장 등록
3. **현장** — 구직자 폰으로 `/make?partner=XXXX` 접속 유도 · 대리는 **결제·생성 대행 최소화**(본인 계정 대리결제 금지)
4. **집계** — 코드별 GMV·건수 시트/DB
5. **정산** — 법인: 주·월 리포트 → 이체 · 개인: 주(→일/준즉시) 리포트 → 이체
6. **품질** — 불만·환불·여권 오안내 시 코드 정지

### 대리에게 주는 것
- 전용 URL + QR PNG
- 30초 안내 스크립트
- 전후 샘플(갤러리 링크) · B2B 브로슈어 PDF(선택)
- 실적 요약 (법인 주·월 / 개인 주·일)

### 대리에게 요구
- 금지 카피 준수 (여권·관공서·가맹 공식 표기 ✗)
- 자기결제·코드 재판매·공개 쿠폰 나열 ✗
- 개인정보(구직자 사진)를 대리 기기·카톡에 **보관·전달 ✗** — 본인 폰에서 직접 진행

## 16. 정산 프로세스 (온라인 · 자동화)

> 질문 잠금: **온라인 가능 ○ · 완전 자동은 단계적**.  
> 주문에 `partnerCode`/`ratePctSnapshot` 있음 · 장부는 메모리(`agentLedger`) → **durable DB·실송금은 아직**.

### 16-1. 한 줄 흐름

```text
결제 confirm 성공
  → 주문에 partnerCode + rateSnapshot + agentType(법인|개인) 저장
  → 타입별 주기 집계 (환불·차지백 차감)
       법인: 월 또는 주
       개인: 주 (목표 일/준즉시 · 환불 홀드)
  → 대리점 확인(대시보드·엑셀)
  → 이체 (수동 → 나중에 자동)
  → 세금계산서 또는 원천 기록
```

### 16-2. 단계

| Phase | 이름 | 온라인? | 자동? | 내용 |
|-------|------|---------|-------|------|
| **P0 파일럿** | 수기 | 반온라인 | ✗ | 대리점 마스터 시트 · 수기 · **이체는 사업자 후** · 개인 즉시 약속 ✗ |
| **P1 온라인 집계** | 대시보드 | ○ | 집계만 | 코드 귀속 · 정산서 자동 · **송금=승인** · 법인 주·월 / 개인 **주** |
| **P2 자동 송금** | 페이아웃 | ○ | ○ | cron: 법인 주·월 · 개인 **일/준즉시**(홀드 후) · 실패만 사람 |

권장: **먼저 P1**. 개인 일·준즉시 송금은 P2 + 환불 홀드.

### 16-3. 정산 대상 이벤트

| 포함 | 제외·차감 |
|------|-----------|
| Toss **confirm 성공** + `partnerCode` 있는 주문 | 결제 전 이탈 |
| 금액 = `amountKrw` (추가컷·레이아웃도 같은 코드면 포함 여부 정책으로) | 환불 승인·차지백 → 해당 인센 **차감/다음 달 상계** |
| rate = 주문 시점 스냅샷 (기본 20%) | 자기결제·어뷰징 코드 → 전액 제외 |

**추천 귀속 시점:** `markPaid` / checkout confirm 성공 시.  
(다운로드 여부와 무관 — 이미 컷 제공 정책과 맞춤. 환불되면 차감.)

### 16-4. 파트너가 보는 온라인 화면 (P1)

- 이번 달 / 지난달 GMV · 건수 · 예상 인센(20%)
- 건별: 주문일 · 금액 · 상태(확정/환불차감)
- 정산 상태: 집계중 / 지급대기 / 지급완료
- 계좌·사업자/주민 정보는 **최초 1회 등록** (암호화 저장)
- **출금 버튼 없음** — 월 배치만 (어뷰징·세무 단순화)

### 16-5. 본사 운영 (P1)

1. 매월 1일 cron: 전월 확정분 리포트 생성  
2. 운영자 검수 (이상 코드·환불)  
3. **승인** → 이체 리스트 확정  
4. 이체: 초기엔 인터넷뱅킹 일괄 · 이후 Toss Payout/오픈뱅킹  
5. 파트너에 알림(카톡/메일): 지급액·이체일

### 16-6. 자동 송금 (P2) 조건

- [ ] 주문·파트너 durable DB (Upstash/DB)
- [ ] 사업자 등록 · 원천/세금계산서 프로세스
- [ ] 실PG 라이브
- [ ] 송금 API 계약 (토스페이먼츠 지급대행 등)
- [ ] 최소 지급·홀드(예: 결제 후 14일) · 실패 재시도

완전 자동이어도 **이상 거래 플래그 시 사람 승인**은 남김.

### 16-7. 파일럿(지금) 실무

| 할 일 | 도구 |
|-------|------|
| 코드 발급 대장 | 시트: code / 이름 / 연락 / rate |
| 결제 추적 | 당분간 수기 또는 UTM·메모 · **코드 붙이기 전엔 정확한 자동 정산 ✗** |
| 파트너 안내 | 「실적은 기록 · 현금 정산은 사업자·시스템 후」 |
| 당근·SNS | 모집·유입 OK · **정산 약속 날짜 확정 문구 조심** |

### 16-8. 답 요약

| 질문 | 답 |
|------|-----|
| 온라인으로 될까? | **됨** — 파트너 실적·정산서 웹 (P1) |
| 자동으로? | **집계·정산서까지 자동 → 송금은 승인 후 자동(P2)** |
| 지금 당장? | 시트+수기 · 이체는 사업자 후 · partner 코드 구현이 선행 |
